# План до запуска

> [!summary] Цель
> До **31 декабря 2026** передать Honey Flowers готовый продукт: приложение «Медовая карта» для клиентов, флористов и владелицы и **склад** внутри него. Продукт работает в аккаунте магазина, сотрудники обучены, данные защищены, есть резервные копии. Ошибок, которые теряют деньги, мёд или остатки, нет.

Документ общий для всех чатов проекта. Каждый чат начинает работу с него, а затем читает [[Honey Flowers — контекст проекта]], [[Спорные вопросы]] и, если работает со складом, [[Склад — архитектура]].

---

## 1. С чего начинаем (27.11)

- **Прототип от 10.11 не закоммичен.** Он лежит в папке ноутбука, а в GitHub и на полигоне — версия от 24.10. Первый шаг — зафиксировать прототип как базу (раздел 6, шаг 0), иначе чаты начнут с разных версий.
- **Что есть в прототипе:** программа лояльности по анкете владелицы, согласие перед регистрацией, тема по логотипу и склад (каталог, поставки, сборка по FIFO, витрина, продажа с мёдом, свежесть, списания), 422 автотеста. Всё сделано «по шаблону» и ещё не проверено живыми людьми на телефонах.
- **Чего нет:**
  - склад — инвентаризация, сверка с кассой и таблицей, фото, продажа поштучно, уценка;
  - продажа и мёд одним действием;
  - уведомления владелице;
  - продуманный дизайн всех экранов;
  - тексты, проверенные юристом;
  - аккаунт Cloudflare магазина;
  - обучение сотрудников.

## 2. Что значит «готово» (критерии приёмки)

Продукт готов, когда выполнено **всё** ниже. «Без единой ошибки» гарантировать нельзя, поэтому планка измеримая.

1. **Сценарии приёмки** (раздел 7) проходят на настоящих телефонах: iPhone и Android, светлая и тёмная тема, медленный интернет.
2. **Нет открытых ошибок P0 и P1** (раздел 5). Ошибки P2 записаны, владелица о них знает.
3. **Автотесты и полный QA-прогон зелёные** (`npm test`, `npm run qa`, e2e). Каждая исправленная ошибка закрыта тестом, который её ловил бы.
4. **Нагрузка:** 2000 клиентов, год продаж и год склада укладываются в лимиты Cloudflare с запасом минимум в 3 раза. Замеры записаны.
5. **Надёжность:**
   - ежедневная резервная копия базы;
   - восстановление проверено вживую;
   - тревоги о сбоях приходят в Telegram;
   - есть план отката версии.
6. **Безопасность:** проверка кода на уязвимости пройдена, находки P0/P1 исправлены; тестовые функции у заказчика выключены; токены только в секретах Cloudflare.
7. **Владелица подтвердила** правила программы и складские настройки — каждый пункт [[Спорные вопросы]] отмечен ✅.
8. **Тексты правил и согласия** проверены юристом, в них реквизиты ИП.
9. **Пилот:** минимум 5 рабочих дней настоящих продаж в магазине без ошибок P0/P1.
10. **Передача:**
    - аккаунт Cloudflare и бот принадлежат магазину;
    - у сотрудников есть короткие инструкции;
    - у владелицы — руководство и контакты поддержки.

## 4. Как работаем

1. **Один чат — одна ветка — одна папка.** Чат пишет только в свою папку на ноутбуке (раздел 6) и только свои файлы (раздел 3).
2. **Пушит только Мираслав.** Чат по завершении задачи пишет список файлов и готовую команду коммита.
3. **Перед записью в папку чат сверяет файлы:** берёт их с ноутбука и сравнивает с тем, от чего начинал. Если файл изменился, чат сначала разбирается почему, а не затирает.
4. **Окончания строк — CRLF**, как в остальных файлах на ноутбуке.
5. **Каждая задача заканчивается проверкой:** `npm test`, typecheck, сборка и, если затронуты экраны, e2e.
6. **Отчёт Штабу** — короткий блок в конце работы: что сделано, какие общие файлы затронуты, какие миграции, что проверено, что не сделано. Мираслав переносит его в чат Штаба.
7. **Слияние — два раза в неделю (вторник и пятница).**
   - Мираслав пушит ветки чатов.
   - Штаб сливает их в `dev` и прогоняет всё.
   - Штаб даёт команду пуша `dev` → полигон.
   - Чаты подтягивают свежий `dev` в свои ветки.
8. **Полигон бережём:** лимит базы общий для аккаунта. Нагрузочные тесты — только локально. Демо-данные на полигоне — не чаще раза в день.
9. **Секреты** (токены ботов, ключи) не пишем в чат и в файлы. Только в настройки Cloudflare.
10. **Решения, которые меняют правила, деньги или данные клиентов,** принимает Мираслав или владелица. Чат описывает варианты и не выбирает молча.

| Приоритет | Что это | Срок |
| --- | --- | --- |
| **P0** | Теряются деньги, мёд, остатки или данные; утечка; приложение не открывается | Чиним сразу, всё остальное ждёт |
| **P1** | Основной сценарий роли не проходит или проходит неверно | До ближайшего слияния |
| **P2** | Неудобно, некрасиво, редкий случай с обходным путём | По плану; после 20.12 — только с согласия Штаба |
| **P3** | Пожелание | В список «после запуска» |

## 6. Подготовка (делает Мираслав, 27–29.11)

**Шаг 0. Зафиксировать прототип как базу** (PowerShell, в папке `Honey_flowers`):
```
git checkout dev
git add -A
git commit -m "Prototype 10.11: owner rules, consent, brand, stock module"
git push
```
Через пару минут полигон обновится. Проверь @honeyflowers_test_bot и `/health`.

**Шаг 1. Создать ветки и папки для чатов** (там же):
```
git worktree add -b feat/stock    "..\Honey_flowers-stock"    dev
git worktree add -b feat/loyalty  "..\Honey_flowers-loyalty"  dev
git worktree add -b feat/design   "..\Honey_flowers-design"   dev
git worktree add -b qa/main       "..\Honey_flowers-qa"       dev
git worktree add -b ops/launch    "..\Honey_flowers-ops"      dev
```
Это не копии репозитория, а дополнительные рабочие папки того же репозитория: история общая, у каждой папки своя ветка. Пушить из любой: `git push -u origin feat/stock`.

**Шаг 2. Подключить папки к чатам.** В каждом чате проекта подключи к компьютеру его папку из таблицы раздела 3. Штабу — основную `Honey_flowers`.

**Шаг 3. Инструкция проекта.** Вставь текст из `docs/Инструкция проекта.md` в инструкции проекта. Этот файл, [[Спорные вопросы]] и контекст-документ добавь в материалы проекта.

**Шаг 4. Стартовые сообщения.** Каждому чату — его стартовое сообщение из раздела 9.

## 7. Сценарии приёмки (что проверяем на телефонах)

Полный список с шагами ведёт чат QA в `docs/qa/Сценарии приёмки.md`. Минимум:

**Покупатель**
- Первый вход: правила → согласие → номер → карта с 15 000 приветственного мёда.
- Покупка в магазине по QR и по коду: мёд, сота и уровень меняются сразу, бот присылает сообщение.
- Покупка через доставку по номеру, пока клиента нет в боте. Затем клиент заходит в бот — карта уже с начислениями.
- Подарок за соту, скидка ко дню рождения, выбор одной скидки из двух.
- Сгорание: предупреждения за 14/7/1 день, сгорание через 180 дней, сброс уровня через 90 дней.
- Узбекский язык во всех экранах и сообщениях бота.

**Флорист**
- Поставка в сумах и в долларах, построчно и одной суммой.
- Сборка букета: себестоимость, подсказка цены, «не хватает».
- Продажа: клиент найден, мёд списан или начислен, подарок выдан.
- Витрина: продажа позже, разборка.
- Списание до и после 200 000.
- Отмена ошибочной продажи.
- Попытка начислить себе — отказ.

**Владелица**
- Правила, команда, клиенты и карта клиента, ручная корректировка мёда.
- Склад: остатки, подтверждение списаний, отчёты по марже.
- Инвентаризация, сверка дня с кассой.
- Кабинет на компьютере: фильтры, выгрузки, импорт клиентов.

**Сбои**
- Пропал интернет посреди продажи, двойное нажатие, два флориста продают последние цветы.
- Приложение открыто сутки, бот перезапущен, база на пределе лимита.
