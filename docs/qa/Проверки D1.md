# Проверки D1 на настоящем Cloudflare (C3 / M0)

Нужно чату «A. Склад» к **04.12**. Вопросы из [[Склад — архитектура]], §10.8, и задача C3 в [[Задачи чатов]]:

1. **Откат пакета.** Если в `db.batch([...])` падает один оператор, откатываются ли все остальные? Если нет, сохранение лояльности (`client_versions`) и продажа склада ненадёжны.
2. **Операторов в пакете.** Сколько операторов принимает один пакет и какая ошибка при превышении. Ежечасная задача лояльности уже пишет 767 операторов одним пакетом ([[Ошибки]], HF-009).
3. **Записи триггеров.** Входят ли строки, которые пишет триггер, в `meta.rows_written`, а значит и в дневной лимит. Бюджет склада считает, что входят.

Попутно, почти бесплатно: текст `RAISE(ABORT, …)` доходит до Worker'а; `PRAGMA foreign_keys` включён; `changes()` виден следующему оператору пакета; предел 100 параметров; `json_each(?)` с параметром 100 КБ – 1,9 МБ; сколько отдельных запросов к базе выдерживает один вызов (50 подзапросов на Free); строки индексов, частичного индекса и `ON CONFLICT DO UPDATE` в `rows_written`.

## Как устроено

`scripts/d1-probe/` — отдельный одноразовый Worker `honey-m0` с **отдельной** базой `honey-m0`. Он не подключён к GitHub, его деплоят руками один раз. Каждая проверка создаёт свои таблицы с префиксом `p_` и в конце удаляет их, поэтому прогон можно повторять. Без ключа `PROBE_KEY` Worker отвечает 403: чужой человек не потратит лимит аккаунта.

**Сколько стоит лимита.** Полный прогон пишет около 9 000 строк (в основном проверка пакета на 5 000) и читает несколько тысяч. Это ~9 % дневного лимита записей бесплатного тарифа (100 000), общего с полигоном. Один-два прогона в день безопасны.

## Что сделать Мираславу (≈ 10 минут)

PowerShell, в папке `D:\c disk\Desktop\Honey_flowers-qa` (после `git pull`, когда эти файлы придут в `qa/launch`):

```powershell
cd scripts\d1-probe

# 1. Войти в НАШ аккаунт Cloudflare (откроется браузер). Если уже входил — пропусти.
npx wrangler login

# 2. Создать отдельную базу. Команда напечатает database_id.
npx wrangler d1 create honey-m0
```

3. Открой `scripts\d1-probe\wrangler.toml` и вставь напечатанный `database_id` вместо `PASTE-DATABASE-ID-HERE`. **Этот файл с id не коммить** — после проверок верни как было: `git checkout -- wrangler.toml`.

```powershell
# 4. Выложить Worker
npx wrangler deploy

# 5. Ключ доступа: сгенерировать и вставить, когда wrangler спросит значение
[guid]::NewGuid().ToString("N")      # скопируй напечатанную строку
npx wrangler secret put PROBE_KEY    # вставь её
```

6. Открой в браузере по очереди (вместо `<КЛЮЧ>` — ключ из шага 5; адрес `honey-m0.<поддомен>.workers.dev` печатает шаг 4, у нас это, скорее всего, `honey-m0.yuldashevbaburbob.workers.dev`):

| # | Адрес | Сохранить как |
| --- | --- | --- |
| a | `https://honey-m0.<поддомен>.workers.dev/run?key=<КЛЮЧ>&only=rollback,raise,fk,changes,params,json,rows` | `docs/qa/d1-probe/run-checks.json` |
| b | `…/run?key=<КЛЮЧ>&only=batch&sizes=100,500,1000,2000,5000` | `docs/qa/d1-probe/run-batch.json` |
| c | `…/subreq?key=<КЛЮЧ>&n=49`, затем `n=50`, `n=51`, `n=60`, `n=1000` | один файл `docs/qa/d1-probe/subreq.txt`, ответы подряд |

Ответ — JSON на странице: «Сохранить как…» или скопировать текст в файл. Ключ в файлы не попадает: в ответах его нет.

7. Cloudflare → **Storage & Databases → D1 → honey-m0 → Metrics**: запиши «Rows written» и «Rows read» за последний час в `docs/qa/d1-probe/metrics.txt` или пришли скриншот. Это проверка честности `meta.rows_written`: база отдельная, поэтому всё, что в ней записано, — наши проверки.

8. Напиши мне «прогон готов». Дальше разбираю я: заполняю таблицу ниже и отдаю вывод Складу.

**После 04.12** Worker и базу удалить (если не понадобятся для C7 — учений восстановления):
```powershell
npx wrangler delete honey-m0
npx wrangler d1 delete honey-m0
```
